Teal Emergency Recovery Screen

exynos-loke-rescue rescue-boot -a ./stock/AP_*.tar.md5

• Flashes signed boot.img, vbmeta.img, and recovery.img.
• Sends CMD_SESSION_END (0x67) to clear bootloader emergency flag.

②

Recovery Prompt & Broken Power Key

Stock recovery prompts: "Cannot load Android system. Your data may be corrupt." but physical Power button cannot confirm.

exynos-loke-rescue emergency-wipe-reboot

• Enters Download Mode via Vol Up + Vol Down + USB insertion.
• Sends opcode 0x64 (0x07) hardware NAND wipe on USERDATA.
• Auto-reboots directly into One UI without touching the Power key!

③

Full Stock OS Reinstallation

Device bootloops past Samsung logo, dynamic partitions corrupted, or restoring 100% clean One UI stock ROM.

exynos-loke-rescue full-raw-restore -s ./stock -e

• Flashes 5.3 GB SUPER, plus DTBO, BOOT, VBMETA, RECOVERY.
• Bypasses samloader-rs super metadata decompression crash bug.

④

FAIL! (Auth) / VaultKeeper Prenormal

Flashing custom recovery / kernel fails with LOKE error code -1: Custom Binary Blocked by OEM Lock.

exynos-loke-rescue rescue-boot -a ./stock/AP_*.tar.md5

• Boot One UI, connect to Wi-Fi, wait 5 min for Samsung KG server check.
• Verify Settings > Developer options > OEM Unlocking is permanently active.

Strict Flash Protection Matrix

To prevent permanent hardware bricking or IMEI loss, exynos-loke-rescue enforces invariant partition protection at the protocol layer.

🛡️ Hard Write-Protected Partitions (Immutable)

  • EFS / SEC_EFS: Radio calibrations, device IMEI & MACs. Overwrite causes permanent modem brick.
  • CPEFS / NVDATA: Cellular modem non-volatile parameter store.
  • TNV / PERSDATA: Factory provisioned trust root keys.

✓ Allowed Flash Targets (Deterministic)

  • BOOT / RECOVERY / VBMETA: Kernel and recovery environments.
  • SUPER: Dynamic OS container (system, vendor, odm).
  • DTBO: Device tree overlays.
  • USERDATA (Erase Only): Format storage without risking radio/firmware.
