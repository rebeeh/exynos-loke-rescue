Odin Wire Protocol Reverse Engineered Specification

Wire-level state machine reconstructed from Samsung LOKE bootloader memory analysis

01 Init

Handshake & Ping

Host sends ASCII string "ODIN" (4 bytes). Bootloader verifies cable and echoes "LOKE".

02 Opcode 0x64

Session Setup

Negotiates protocol tier: Odin v3 (1MB sequence buffer) or Odin v4 (8MB sequence). Hardware NAND erase (subcmd 0x07).

03 Opcode 0x66

Sequence Streaming

Transmits 512-byte aligned macro buffers. On the final sequence block, bootloader validates SHA-256 and OEM RSA public keys.

04 Opcode 0x67

Session Commit

Clears the emergency softbrick flag in secure param storage and executes device reset to One UI.

Protocol Frame Structure (1024-Byte Control Block)

Offset Field Size Description
0x00 - 0x03 cmd_id 4 Bytes (u32 LE) Primary opcode: 0x64 (Setup), 0x65 (PIT), 0x66 (Flash), 0x67 (End)
0x04 - 0x07 subcmd_id 4 Bytes (u32 LE) Subcommand: 0x00 (Start sequence), 0x02 (Commit sequence), 0x07 (NAND wipe)
0x08 - 0x0B arg1 4 Bytes (u32 LE) Payload length or sequence byte count (aligned to 512-byte sector)
0x0C - 0x0F arg2 4 Bytes (u32 LE) Target partition ID from PIT table (e.g. 18 for BOOT, 30 for SUPER)
0x10 - 0x13 arg3 4 Bytes (u32 LE) Final block flag: 1 = verify signature & commit; 0 = stream next chunk
0x14 - 0x3FF zero_pad 1004 Bytes Zero-filled padding to fulfill strict 1024-byte control packet size

Flash Safety Protocol & Invariant Protections

Transport-level verification preventing permanent radio hardware bricking or IMEI loss

Strict Read-Only Partitions (Locked by Engine)

These partitions store factory baseband calibrations and cryptographically anchored device identifiers. Flash writes are blocked at the host level before packet generation.

  • EFS / SEC_EFS: Radio calibrations, IMEI and cellular certificates.
  • CPEFS / NVDATA: Cellular modem non-volatile parameter store.
  • TNV / PERSDATA: Factory hardware keystore trust anchors.
Permitted Flash Targets (Deterministic Verification)

Verified operating system partitions eligible for sequence streaming and cryptographic signature verification by the LOKE bootloader.

  • BOOT / RECOVERY / VBMETA: Kernel, ramdisk, and AVB 2.0 signatures.
  • SUPER: Dynamic system, vendor, product, and odm container.
  • USERDATA: Low-level hardware erase (Opcode 0x64 Subcmd 0x07).
